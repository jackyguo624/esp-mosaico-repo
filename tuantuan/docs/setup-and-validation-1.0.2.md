# 团团 1.0.2 本机设置与验证

## 本轮实现

- Repo 根目录管理共享 Mosaico 工具；团团代码、UI、服务与固件在 `tuantuan/`，其他独立应用使用 `apps/<name>/`。
- 设置新增触屏键盘和本地摄像头扫码。支持连接配置和模型 Key 两种二维码，也支持直接编码的 `sk-...` Key。扫码仅填入确认页，需主动保存。
- Wi-Fi、服务地址和设备连接口令保存到团团原有 NVS 命名空间。模型 Key 通过已配对服务保存到电脑配置，不写入设备 NVS。
- 输入秘密字段默认遮盖，编辑完成或离开页面时清理编辑缓冲；服务日志不包含配置值。
- UI 仅提交发生变化的内容，避免重复刷新拖慢输入；任务等待保存、失败保留详情、空任务隐藏无效行。

## ASR 与 TTS 的实际流程

触屏开始/结束录音 → 设备生成16kHz、16bit、单声道 WAV（最多20秒） → 局域网传到电脑 → Faster-Whisper small、CPU int8、本地 VAD 中文识别 → 识别文字发送 DeepSeek → 电脑使用 macOS `say` Tingting 合成 → 转换为16kHz PCM → 设备播放。

ASR/TTS 在电脑本地执行；DeepSeek 接收识别文字及任务/短期对话上下文。当前仍是整段录音后识别、整句回答后合成，未实现流式对话、唤醒词或边播边说。

本轮语音改动：

- 启动服务后后台预加载模型，`/health` 与 `/v1/state` 提供就绪状态。
- 已校验的标准 WAV 直接转换为采样数组交给模型，避免重复媒体解码，并修复本机 PyAV 解码接口不兼容导致识别失败的问题。
- 固定中文、启用 VAD、默认 beam size 3 和4个 CPU线程；配置允许调整。
- TTS 使用默认8MiB的内存 LRU 缓存，最多32MiB，可设0关闭。缓存区分文字、音色、语速和引擎，重启服务后清空。

本机合成音频测试“你好团团，提醒我明天早上九点喝水。”：音频4.22秒；首次合成约0.53–0.59秒，缓存命中约0.00001秒；模型预加载后识别约3.52秒，内容和提醒时间正确。该结果来自合成语音，不代表真机麦克风、噪声环境或完整网络对话延迟。

设备更新后，用另一句合成问候连接真实 DeepSeek 测试：ASR约1.10秒、模型约0.82秒、TTS约0.57秒，总计约2.48秒；回答音频约7.07秒。测试使用内存数据库且任务操作为空，未修改用户任务。该耗时不包含录音和设备网络传输。

## 设备验证状态

本轮在同一台已连接设备上完成实时身份和重启状态校验；设备编号、启动编号、操作记录及原始证据仅保留在本机。原有分区与凭据保持不变。1.0.2 已使用固定 SDK 编译通过，应用约2.1MiB。编译器有一项通用分区提示：应用不能放进保留的 factory 槽；实际安装目标是原有约9MiB的 ota_0，官方工具按该契约制包，未更改布局。

首次 System Update 在旧版 Vibe Mode 0.1.2 中中断并发生看门狗重启。原始操作、状态、日志及转储已在本机归档；转储的 ELF 不匹配失败时固件，不能据此确认具体源代码触发点。

经用户确认，使用仓库评审包完成仅含 factory 组件的 Vibe Mode 0.1.4 自更新，保持布局、不写入用户数据。随后团团1.0.2完整更新成功，健康启动、崩溃计数0，ELF SHA-256为 `708d567f710942b00c5985cb6861ac246572639ab765313c0c091fddf2183f8f`。真实设备截图已检查，新界面正常显示；约154KiB片内内存和13MB PSRAM可用。该阶段设备显示离线，实际配网与麦克风验证尚未完成；后续摄像头验证见 [1.0.3记录](camera-fix-1.0.3.md)。

## 本机运行

电脑服务地址填写为 `http://<电脑局域网IP>:8765`（地址可能随网络改变）。服务配置在 `server/config.env`；请仅在本机编辑，不把 Key 或连接口令粘贴到聊天中。运行 `server/start.command` 可启动服务；ASR模型已缓存，首次加载后可离线识别。

二维码生成见应用 README。连接二维码生成器会在本机终端提示输入Wi-Fi密码，不回显；Key二维码直接读取本机配置。中文Wi-Fi名称推荐二维码输入，触屏键盘当前仅支持英文、数字和符号。
